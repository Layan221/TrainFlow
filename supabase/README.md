# إعداد TrainFlow

الواجهة تدعم اتصال Supabase عند إضافة الإعدادات. لم يتم الاتصال بمشروع حقيقي أو إرسال بريد أثناء تجهيز المشروع.

## إعداد المشروع

1. أنشئ مشروع Supabase جديدًا، ونفّذ `schema.sql` في SQL Editor مرة واحدة. يحتوي على الجداول، القيود، وسياسات RLS. لا تنفّذه فوق جداول موجودة دون مراجعة وترحيل.
2. من Authentication فعّل Email وتأكيد البريد، وأضف عنوان الموقع إلى Site URL. أضف العنوانين الكاملين `https://YOUR-SITE/login.html` و`https://YOUR-SITE/reset-password.html` إلى Redirect URLs. استخدم HTTPS في النشر.
3. جهّز SMTP للبريد الفعلي واختبر رسالة التأكيد ورسالة الاستعادة. احتفظ بقالب الاستعادة الافتراضي الذي يستخدم `{{ .ConfirmationURL }}`. فتح الرابط يتيح تحديد كلمة المرور الجديدة؛ لا يوجد رمز استرداد داخل الحساب.
4. في `supabase-config.js` أضف `url` و`publishableKey` العام فقط. المفتاح العام ليس سرًا؛ حماية البيانات تعتمد على RLS. لا تضع `service_role` أو `sb_secret_` في ملفات الموقع.
5. اربط Supabase CLI بالمشروع، وانشر الدالة `manage-accounts`. يُضبط `verify_jwt = false` لأن مسار إنشاء المشرف يعمل قبل الدخول؛ الدالة تتحقق من JWT عبر `auth.getUser` لكل إجراء إداري، ثم تتحقق من الدور وعلاقة الإشراف.
6. في أسرار Edge Functions أضف `SITE_ORIGIN` بعنوان الموقع دون شرطة نهائية، و`SUPERVISOR_REGISTRATION_CODE` بقيمة قوية خاصة بالمؤسسة. مفاتيح `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` و`SUPABASE_ANON_KEY` متاحة في بيئة Supabase. لا تنقلها إلى ملفات المتصفح. لإيقاف تسجيل المشرفين احذف سر كود التسجيل.

```sh
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy manage-accounts
node scripts/build.cjs
```

انشر محتويات `dist` فقط. البناء يرفض الإعدادات الفارغة والمفاتيح السرية، ويُلزم النسخة المنشورة بالاتصال السحابي. مجلد المصدر مخصص لـGitHub والتطوير؛ ملفات الاختبارات وأدوات التطوير لا تدخل ضمن ناتج البناء.

## البيانات والصلاحيات

- المشرف يرى متدربيه ومهامهم وتقاريرهم؛ المتدرب يرى بياناته ومهامه وتقاريره ومعلومات مشرفه.
- المتدرب لا ينشئ حسابًا؛ ينشئ المشرف الحساب ويغيّر كلمة مروره عبر دالة خادمية. كلمات المرور مخزنة لدى Supabase Auth، وليست في جدول profiles.
- تقارير الأيام السابقة محفوظة وتظهر للطرفين. تقرير واحد لكل متدرب وتاريخ، ويمكن لصاحبه تحديث المحتوى. المهام المكتملة تبقى في سجل المهام ويمكن تصفيتها بالحالة.
- حذف المتدرب يحذف حساب Auth وملفه والمهام والتقارير المرتبطة به.
- إن فشل حفظ ملف المشرف بعد إنشاء Auth، راجع حساب Auth غير المرتبط قبل إعادة التسجيل؛ لا تحذف الدالة حسابًا قد يكون موجودًا مسبقًا.

## المعاينة قبل الربط

`node serve.cjs` يشغّل المعاينة على `http://127.0.0.1:4173`. عند ترك الإعدادات فارغة تُستخدم بيانات المتصفح السابقة فقط، ولا يُرسل بريد. هذه المعاينة ليست نسخة إنتاج، ولا تُرحَّل كلمات مرورها أو حساباتها تلقائيًا إلى Supabase. أنشئ الحسابات في Supabase بعد الربط. رمز اعتماد المعاينة القديم محصور في المعاينة؛ كود الإنتاج يُفحص على الخادم.

## التحقق بعد الإعداد

اختبر على مشروع تجريبي: تأكيد مشرف جديد، دخول الطرفين، إنشاء متدرب وتغيير كلمة مروره، إرسال تقرير وتعديله من جهاز آخر، رؤية المهام المكتملة، واستعادة كلمة المرور من البريد مع رابط صالح ورابط منتهي. تحقّق باستخدام مشرفين ومتدربين مختلفين من رفض قراءة أو تعديل سجلات الآخرين، حتى عبر REST مباشرة. اختبارات المتصفح المحلية والمحاكاة لا تحل محل هذه الخطوة.

المراجع: [استعادة كلمة المرور](https://supabase.com/docs/guides/auth/passwords)، [تغيير كلمة المرور من الخادم](https://supabase.com/docs/reference/javascript/auth-admin-updateuserbyid).
